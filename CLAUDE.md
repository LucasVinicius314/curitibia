# Curitibia (Godot remake)

Voxel co-op prototype remade from the old Unity project (see `GODOT_REMAKE_PLAN.md`; the Unity code is in git history before commit `1431b1c`). Godot 4.7.2 mono, **C# only**, Jolt, Forward+, D3D12. Follows the user's global `godot-games` conventions; this file wins where it differs.

## Layout
- `src/` by feature: `Core` (no dependencies: `GameLayers`, `Team`, `VoxelMath`, `VoxelRaycast`, `GradientNoise`, `DevArgs`, `Game` autoload = input map in code), `World` (terrain, chunks, mesher, generator), `Player`, `Enemies`, `Combat`, `Net`, `UI`; `Main.cs` is the world scene script.
- `scenes/` (menu, main), `prefabs/` (player, hud), `data/*.tres` (tuning as `Resource`s: `world_gen`, `player_tuning`), `assets/textures`, `tests/Curitibia.Tests` (xUnit), `libs/p2p-signaling-server` (git submodule, **never edit**), `scripts/fetch-webrtc.*`.
- Terrain, chunks and meshes are built in code (procedural); player/enemy/projectile prefabs and the HUD's always-on labels are scenes with `[Export]` node refs (`node_paths=` in the `.tscn`). **Menus and overlays are built in code** from the shared theme in `UI/Ui.cs` (pages, lists and cards are dynamic): `MainMenu` (Main/Host/Join/Settings pages, friends' rooms, friend management, server address) and the HUD's toast, Tab roster, "Joining" card and pause menu. Use `Ui.Label` (single line, safe in a row) vs `Ui.Paragraph` (wraps; columns only: a wrapping label in a row collapses to one letter per line).

## Rules specific to this project
- **Engine-free code stays engine-free** (`VoxelMath`, `VoxelRaycast`, `GradientNoise`, `Blocks`, `WorldGenerator`, `ChunkMesher`): no `using Godot`, so `tests/` links them. Add a test with any change to them. Run: `dotnet test tests/Curitibia.Tests`.
- Terrain generation is a pure function of (seed, chunk coord): the host sends only the seed plus the edit list, never terrain. Do not make it depend on anything per-peer.
- Chunk data is a `ChunkData` (`Core/ChunkData`, engine-free): `VoxelMath.ChunkHeight` = 1152 layers, stored in 16-layer **sections**, each in its cheapest form: one block all through (rock for hundreds of layers, open sky: no memory), a two-block bitmask (rock with caves: 2 KB) or a full array (the few surface sections with many kinds of block: 16 KB). Read with `Get`, write with `Set` (it changes the form as needed), call `Compact()` after bulk generation; reads outside the world are air. Block ids in `BlockIds`. **A voxel is `VoxelMath.BlockSize` = 0.5 m**: block edits, chunk data, the generator, the raycast and the pathfinder all speak voxel coordinates; bodies, cameras and physics speak metres. Convert with `VoxelMath.WorldToVoxel` / `VoxelToWorld` / `VoxelCenter` (the mesher stays in voxel units, `ChunkBuild.From` scales the vertices). `Terrain.SurfaceHeightAt` takes a voxel column and returns metres. World coordinates use `VoxelMath.WorldToChunk` (floor division on negatives). **Layers vs Y:** code uses the storage layer everywhere; the game shows `VoxelMath.DisplayY(layer)` = layer - `SeaLevel` (700), so Y 0 is the surface baseline (the biome offsets are added to it), the world bottom is Y -700 and mountains reach about Y +330. Only display code converts.
- **Multiplayer = Godot's multiplayer API over p2p-signaling-server** (host = peer 1). `NetSession` is the autoload at `/root/NetSession` (RPC path must match on every peer). Players are built by a `MultiplayerSpawner` with a custom `SpawnFunction` in `Main` (node name = owning peer id = authority). Host-authoritative world: clients *request* block edits (`RpcRequestSetBlock`), the host validates (reach, rate, block id) and broadcasts. Players replicate `Sync*` properties via `MultiplayerSynchronizer`; animation is computed locally from replicated velocity.
- The p2p wiring rules (assign the peer in `PeerCreated`, RPCs only after `ConnectedToServer`/`PeerConnected`, library compiled into this assembly, `addons/webrtc_native` present) are in `libs/p2p-signaling-server/docs/integration-guide.md`: read it before touching networking. Bucket `curitibia`. **The game contains no server address.** The library resolves it (game `Url` if set, which we never do; else `P2P_SIGNALING_URL`; else the shared `~/.p2p-signaling-server/server` file; else `no_server_url`). The menu's Settings page writes that file (`Net/ServerSettings`); never set `P2PLobby.Url`, because the library would save it as every game's default. `--net-url` sets the env var for one run only. **The player name is shared the same way** (`~/.p2p-signaling-server/name`, shared with every game on the machine): `Net/PlayerProfile` reads it (OS user name until one is chosen) and the menu's name field saves it with `P2PIdentity.SavePlayerName`; `--net-name` is for one run only and never writes it.
- **Enemies do not use a baked navmesh**: the world streams and is edited, so `Enemies/VoxelPathfinder.cs` (engine-free, tested) does A* over walkable voxel cells. Enemy AI runs only on the host; others interpolate replicated state. Enemies, projectiles and players are all created by `MultiplayerSpawner`s with custom spawn functions (every peer builds the node from the same data).
- Damage goes through `IDamageable` + `DamageInfo` and is applied on the host only; `Health.Hp` is replicated by a synchronizer the host owns.
- **Smooth motion: physics stays at the default 60 Hz (do not raise it for smoothness) and engine physics interpolation is OFF.** Bodies only move on physics ticks, so on a high-refresh monitor most rendered frames showed no motion (measured: camera speed swinging 0 to 13 m/s while walking at 5). `Core/TickSmoother` keeps the last two tick positions and `PlayerController._Process` (camera) and `Enemy._Process` (host-side visual) sit between them with `Engine.GetPhysicsInterpolationFraction()`; that alone brought the spread to 0.005 at 60 Hz. Anything new that moves on physics ticks and is seen up close needs the same; remote bodies are smoothed per frame toward the replicated state. A higher tick rate costs CPU and network (every synchronizer sends per tick) for no visual gain once this is in.
- **Player controls and tools:** hold Space keeps jumping, Shift sprints, V toggles third person (camera pulled in by a voxel walk, no physics query), F toggles noclip flight (`--noclip` starts in it; Space up, Ctrl/C down). **Items** (`src/Items`): `ItemDef` resources in `data/items/*.tres` (stable `NetId`, name, stack size, `Infinite`) with a `Behavior` (`SwordBehavior`, `PlaceBlockBehavior`: `OwnerUse` runs on the owner, `HostUse` on the host after an announced use) and a `Model` (`SwordItemModel`, `BlockItemModel`; shown in hand and rendered once into the hotbar icon by `ItemIconRenderer`). New item = a `.tres` plus a line in `ItemRegistry`. `Inventory` (hotbar, owner-local for now: blocks are infinite; make it host-authoritative before items become finite), `ItemUser` (buttons to use, one RPC for announced uses), `HeldItemDisplay` (held model from the replicated `SyncHeldItem`). Primary uses the item (swing, break), secondary places. Enemies are **melee only** and have `Health` (they die on the host and the spawner removes them). Ping is measured by `NetSession` (client pings the host once a second, the host broadcasts everyone's value); the HUD shows it on screen and in the roster. The pause menu has a Settings view (`UI/SettingsPanel.BuildScreen`: a full-screen view with a sidebar of categories Video/World/Controls/Debug (+ Network on the main menu), dense rows from `Ui.Compact`, shared by the main menu and the pause menu; descriptions are the small text under each row; new settings are a row in `SettingsPanel`).
- **Underground** (`World/Underground.cs`, engine-free, tested in `CaveTests`): Y 0 down to -500 is the caverns, -500 to -700 the underworld (`Underground.HellTop`). Rock is stone down to the underworld and `Hellrock` in it; the lowest 3 layers are never carved; open space in the lowest 28 layers is `Magma` (a solid block for now: there is no fluid, no damage and no light yet). `CaveCarver` carves from 3D gradient noise `GradientNoise.Sample(x, y, z)`: tunnels where two noise fields are both near zero, caverns where a slower third is high, both opening with depth, and the underworld nearly all open (about 7% open in the caverns, about 32% in the underworld). The noise is measured at the corners of 4-voxel cells and blended, and a cell whose corner range cannot reach a cave is skipped, which keeps a chunk at about 30 ms. A 10-voxel crust stays under the surface except where a 2D noise opens cave mouths. `Underground.NameAt`/`Terrain.UndergroundAt` name the layer (shown on the minimap and as a region banner). **Meshing is windowed** (`Terrain.WindowFor`): a chunk nobody is near is drawn from 24 layers under its surface up; **every chunk in render distance, for a viewer that is underground** (the slider applies underground exactly as on the surface; a cap on the distance made caves vanish past 48 m) are drawn as a slab from 64 layers below to 96 above the viewer, so only what can be seen is meshed (without it a viewer in the underworld meshed the whole column: 1.7 GB RAM). A viewer that is on or less than about 40 layers under the ground still gets the surface mesh, but its chunks' window is extended down to the section below the viewer, so a body is always inside its chunk's mesh window (a cave just under the surface otherwise left the feet under the window, and the collision check froze the player there). **Performance of streaming:** measured with temporary timers, the main thread's cost was nearly all building collision shapes (about 5 ms per chunk, 15 ms for underground ones with 20-40k triangles of cave wall); meshing and generation are already on worker threads (`Task.Run`, cores - 2 in flight). So only chunks within `CollisionRadius` (4) of a viewer are meshed with collision (`ChunkBuild.WithCollision`; a chunk entering the radius is remeshed with it; anything that must collide with the world has to stay within about 64 m of a player), mesh uploads are time-budgeted (`ApplyBudgetMs`) instead of a fixed count, and the underground slab is 48 layers below and 64 above the viewer's band of 4 sections (64 layers), moving only when the viewer leaves the band so changing height does not remesh everything; measured at render distance 12: caverns 1.26 GB VRAM, 1.9 ms GPU; underworld 1.5 GB VRAM, 2.5 ms GPU, about 155 FPS (drawing every chunk full depth was 4.7 GB, 8-13 ms). If walking still hitches, measure again before guessing; the next levers are a smaller slab, fewer triangles per cave wall, or building the collision off-thread. **Underground light (stand-in):** there is no light engine, and the slab meshes stop 64 layers above the viewer, so the sun used to shine into caves. `World/CaveLight` fades the sun and the sky ambient out by how much **sky the eye can see** (`CaveLight.SkyExposure`: 13 rays in a cone up from the head, 60 m long, a block takes all of a ray's light except leaves (5% each) and trunks/cactus (20% each); the weighted average, smoothed from 0.2 dark to 0.55 bright, is checked 5 times a second and faded every frame). A wide hole in the ground is bright, a narrow shaft or a roof is dark, a tree barely matters (an earlier version used one ray straight up and counted leaves as a roof; one using only depth below the terrain darkened a wide open pit). Deeper than 40 m below the terrain it is always dark (also keeps the underworld hall dark). Direct sun is the real directional light with its shadows. The lamp is small (9 m, `OmniLight3D`) and black exponential fog thickens underground (the first version had an 18 m lamp, which lit a whole cave and looked like no darkness at all). The window caps are the near-black **void tile** (the last atlas tile, `tileCount - 1`), so a cut through open space reads as depth, not as a stone wall. **Measured: the meshing window is not optional**: without it VRAM goes from 0.5 GB to 4.7 GB, GPU time from 1 ms to 8-13 ms and load from 6 s to 22 s (every chunk in view meshes every cave wall down to the bottom). A real answer is per-voxel light (sky light flood fill + block light for magma), not done. **Collision is greedy-merged:** `ChunkMesher.MergeCollision` merges the exposed faces of each plane into rectangles whatever their block (the test proves the area equals the visible faces' area exactly, with about 2.2x fewer triangles), which halved collision build time on the main thread; measured walking at 10 m/s: about 155 FPS, no frame over 25 ms. Workers are not the bottleneck (generation about 45 ms and meshing about 8 ms per chunk, nothing queued). **Step-up:** `PlayerController.TryStepUp` decides wall-or-step with a short (0.25 m) probe from the raised position; the old full body-width probe ran into the next riser of a staircase (steps are only 0.5 m deep) and refused to climb. Verified by walking a built staircase in the engine (and the player used it fine). **Render distance** is a player setting (`GameSettings.RenderDistance`, 4 to 16 chunks, default 12, saved in settings.cfg, a slider in the shared settings panel, applied live: `Terrain` re-plans on `GameSettings.Changed`); `WorldGenSettings.ViewRadius` is unused now. Cost grows with its square (5: 157 chunks, 205 MB VRAM; 12: 729 chunks, about 480 MB). **Streaming order:** `Terrain.Plan` remeshes stale chunks nearest-first before it requests more generation (generation is slow enough that the other order left meshes near the player out of date), and `HasCollisionAt` only counts a mesh that is current and whose layer window contains the body's feet, so the player freezes until the right ground exists instead of falling through a stale one. Where the window cuts through open space the mesher adds a cap face so you never see through the cut (cap faces are **visual only**: `MeshData.SolidIndexCount` keeps them out of the collision, otherwise they are solid stone with no block behind it, which cannot be broken); it remeshes when a viewer moves up or down a section. **Underworld hall:** below the blend band the cavern threshold drops to -0.38 (nearly everything open, about 73% of the hall) and a third noise sampled almost flat in height (`PillarFrequency`, `PillarVertical`) leaves rock standing as tall pillars where it is above `PillarThreshold` (core 0.17; lower = fatter, more pillars; about 7% of columns are full pillars). The pillar noise is only sampled up to the top of the blend band. **Underworld floor:** `CaveCarver.FloorAt` keeps the hall's floor solid (about 84% of it, a rocky plain near layer 38 with a little unevenness) except in magma lakes where a slow 2D noise is low, sloping down to a lake bed at layer 12; open space below `Underground.LavaTop` (28) is magma, so lakes are the only lava. The pillar threshold is 0.27 (about 4% full-height pillars). The meshing window always spans the whole underworld hall near it: down to the bottom of the world and up past the roof through the rock blend band (`HellTop + BlendBand + 16`, Y -424), otherwise looking up from the floor showed the lid of the slab as a ceiling of placeholder chunks that swapped as you rose; the cut left is about 118 m overhead, hidden by the red haze (`low < HellTop` becomes 0 and `high` is raised; `low < HellTop` becomes 0), otherwise its cut and dark cap would cover the lakes. The hellrock texture is a dark charcoal with a slight warm cast (about 66/56/58), a few darker cracks and lighter flecks; no orange (it read as red sand when it was brighter and warmer), the red comes from the underworld light. **Underworld light:** `CaveLight` turns the dark into a red glow with `Underground.AuraBlend` of the player's height (is 0% at Y -450 and 100% at Y -500 (a smoothstep), and the red is blended in with the ambient light's sky contribution rather than by switching the ambient source, because the switch made it start suddenly): red ambient colour at 0.5, a red fog haze (density 0.016, lit) and a bigger orange lamp. **Blend:** stone turns into hellrock gradually over a band of `Underground.BlendBand` = 60 layers either side of Y -500 (patchy, wobbled by 3D noise), and the tunnel width and cavern threshold follow the same smooth `DepthBlend`, so there is no line between caverns and underworld. Tunnels are round (noise `Squash` 1.0; larger makes thin flat strips) and wide (about 16% open in the caverns, 48% in the underworld). **Generation cost:** biome weights are measured on an 8-column lattice (cached per thread, `WorldGenerator.Weigh`) and blended between instead of 9 noise samples per column (1024 columns: 11.6 ms to 1.6 ms); the carver skips cells whose corner range cannot reach a cave, fills fully-open cells without per-voxel noise, and loads corners once per cell; a chunk takes roughly 40 ms on a worker, most of it 3D noise at the cell corners and per-voxel blending in open cells. Not done yet: water at Y 0, light and darkness underground, lava that hurts, ores, enemies below ground, surface structures.
- **Biomes** (`World/Biomes.cs` table, `World/BiomeMap.cs`, both engine-free, tested in `BiomeTests`): three slow noise fields (temperature, moisture, ruggedness) place each column in climate space; the distance to each biome's centre gives a smooth weight. `WorldGenerator.Column` **blends the height by those weights** (borders are slopes, not cliffs; a biome = base offset + relief + `Ridged` mix of rolling and ridged noise) and the strongest weight picks the blocks (surface, filler, stone; `SnowLine` caps mountains) and the tree density. Ruggedness is damped near the origin so spawn is never in mountains. The mountains are a massif of their own: `WorldGenerator.Column` lifts the ground by `RampUplift` (160 voxels) as the mountain biome's lead over its strongest rival grows from 0 at the border to `RampLead` (a few hundred metres in; the lead is exactly zero at the border, so lowland beside a range is untouched), then by `CoreUplift` (45 more) as the ring-averaged ruggedness (`BiomeMap.Weights` out parameter) keeps rising toward the heart; so the biome's baseline is about where its peaks used to be and its large relief with sharp ridges (squared ridge noise, Ridged 0.9) stands on top, up to about 380 voxels. Plains have almost no relief. `BiomeTests` guard it (mountain median vs plains median, mean slope per biome, no lowland above about 130). New biome = a `BiomeId` and a line in `Biomes.All` (plus blocks/tiles in `BlockIds`/`TextureAtlas` if it needs new ones); tune with `Spread`/`RuggednessWeight` in `BiomeMap` and `ReliefScale`/`BiomeFrequency` in `data/world_gen.tres`. Re-check the share and steepness tests after tuning.
- **Border blending:** `ColumnInfo.Biome` is the ruling biome (name, relief, minimap region); `ColumnInfo.SurfaceBiome` is whose surface, filler and trees the column gets. Near a border `WorldGenerator.SurfaceBiomeOf` picks between the two strongest biomes by **distance to the border in voxels** (estimated from the weight lead and its slope, measured `SlopeStep` voxels along each axis, so the mix is as wide on a gentle gradient as on a sharp one: sizing it by weight share made it hundreds of metres wide), mixing within `BlendHalfWidth` (56 voxels, which the patchy noise shrinks to roughly 20-25 m in practice) either side of it. The border is moved about by two scales of noise (`BorderWarp`, `BorderGrain`) and the pick uses a patchy hash (`PatchSize` 3 columns) so it clumps instead of looking like static. The pair is taken in a fixed id order so the distance is signed consistently across the border (do not make it relative to "second": that leaves a faint straight seam where the two swap roles). Anything that wants "what is on the ground here" (blocks, trees, map) uses `SurfaceBiome`; anything that wants "where am I" uses `Biome`/`BiomeAt`. `Borders_mix_the_two_surfaces_instead_of_meeting_in_a_line` guards both the mixing and its width.
- **Regions:** six biomes with display names (Sunlit Plains, Whispering Woods, Sunscar Desert, Frostlands, Verdant Hills, Stonecrown Mountains). The HUD (`UpdateRegion`) samples the player biome four times a second, announces a change with `UI/RegionBanner` after about 0.75 s in it (no flicker on borders) and shows the current name on the third line of the info label. The ruling biome and the height blend both use the biome weights **averaged over a ring of 900 voxels** (`BiomeMap.DominanceRadius`), which folds thin bands and islands into their neighbours (`Little_of_the_world_is_in_tiny_patches` guards it; it costs about 5 ms per chunk). Mountains stay out of roughly 400 m around spawn. Biome size is `BiomeFrequency` (0.00022, regions of 1 to 3 km; `Biomes_are_wide_enough...` guards it, more biomes means shorter stretches, so lower it when adding one).
- **Sword swing** (`Items/SlashSwing`, engine-free, tested in `SlashSwingTests`; `SwingStyle.Slash`): the cut is geometry in one tilted plane through the shoulder, high left to low right. Hand and blade tip travel ovals (ellipsoid sections) around the shoulder, the blade is the hand-to-tip line with the tip running ahead of the hand by a lead that grows through the stroke (the wrist snap), the flat faces the plane normal and the edge faces the travel, so the sword never spins in the hand. Phases: wind-up, cut, settle, recovery (it retraces the arc and only fades into the rest pose late: the end of the cut is about 180 degrees from the rest orientation, so a direct quaternion blend flips). `HeldModel` plays it in first person (shoulder placed ahead of the camera so the whole cut stays on screen) and on the body, where `PlayerVisual.AimRightArm` points the right arm at the grip. Damage lands when the blade passes the middle of the cut (`ItemBehavior.HitDelay` = `SlashSwing.ContactTime`, applied by a timer on the host). Two cuts share the geometry (`SlashArc.Forehand` from high right to low left, `SlashArc.Backhand` from high left to low right) and consecutive swings alternate forehand, backhand, forehand... (`SlashCombo`, every peer counts its own Play calls; a pause of over about a second starts again with the forehand). Tip speed is capped in the tests (about 35 m/s), and the recovery fade must be exactly zero where the cut pose crosses 180 degrees from rest (see the tests).
- **Tree kinds** (`TreeKind`: Oak, Pine, Birch, Cactus) come from the biome (`BiomeDef.Tree`, plus `AltTree` for a share of them: birch among the oaks of plains, woods and hills; pine on snow and mountains; cactus in the desert). Each kind has several shapes (`Tree.Variant`, picked by a hash of the cell: oak round/tall/wide/bush, birch tall/small, pine spruce/slim/fir/young, cactus classic/two arms/barrel/spire), with its own trunk and leaf blocks (`Tree.TrunkBlock`/`LeafBlock`). Trunks are 1 or 2 voxels thick (the 2-wide ones are also taller) (`Tree.Width`: birch always slim, oaks thin to thick, the wide oak thick and flared at the roots), and some oaks and birches bend a voxel at mid-height (`Tree.Lean`); the canopy centres on the trunk top (`CentreX`/`CentreZ`). New kind or shape = an enum value or a case in `TreeFeature.TryGetTree` and `Tree.IsLeaf`/`IsTrunk`; keep it within `MaxReach`/`MaxHeight` (the budget test scans every shape).
- **Map and minimap** (`src/Map`, `UI/Minimap`, `UI/WorldMap`): `MapTileBuilder` (engine-free, tested) turns a chunk into a 32x32 top-down picture (one pixel per voxel column, coloured by the top block, shaded by the slope to the west and north columns; chunk borders look at the neighbour chunk). `MapCache` keeps one Image and texture per chunk for the whole session, redraws up to 8 per frame from `Terrain.ChunkChanged` (a chunk finished generating, or a block in it was edited; the east and south neighbours are redrawn too) and drops everything when `Terrain.WorldVersion` changes; chunks stay on the map after they unload (explored memory, not saved to disk yet). `MapSurface` draws the tiles and the markers (you as an arrow, players cyan, enemies red); the minimap is in the top right and turns with the player (ahead is up, an N marks north; drawn in a rotated canvas frame, see `BeginRotatedFrame`) with the coordinates and region underneath in bright outlined text (= and - zoom); M opens the full-screen map (`WorldMap`: drag, wheel zoom about the cursor, Space centres, M or Esc closes; the pause menu is suppressed while it is open and the player stands still). `--open-map` opens it from the command line. Not done: waypoints, saving explored areas, biome tint on the map.
- **Grass tufts, day/night, natural enemies:** **Short grass** is a block (`BlockIds.ShortGrass`, a *plant*: `BlockIds.IsPlant`): the generator (`WorldGenerator.PlacePlants`, after caves and trees, by a hash of seed and column, about a third of the open grass tops) stores it in the chunk like any block, so it is synced, edited and breakable (`Terrain.IsTargetable` is what the aim ray and the look-at panel use) but not solid (`BlockIds.IsSolid`/`Terrain.IsSolid` are false for it: no collision, enemies walk through, it hides no face of its neighbours, `CaveLight` ignores it, the map reads the grass under it). The mesher draws it as two crossed double-sided quads (atlas tile `BlockIds.TuftTile`, transparent around the blades; the atlas material is alpha-scissor, every block tile is opaque) jittered by a hash of the world column, and adds nothing to the collision (`Short_grass_is_a_plant_block...` guards it). **Day/night** (`World/DayNight`, `GameSettings.DayNightCycle` checkbox in the shared settings panel, saved): the clock is the system clock modulo `DayLength` (10 min), so every peer agrees with no sync; it turns the sun, tints it at dusk, moves the procedural sky colours (the sky ambient follows), and at night the same light is a dim blue moon (`LightStrength`, no sun disc). `CaveLight` multiplies its fade by `DayNight.LightStrength`; `DayNight.IsNight` drives the spawner; off = always noon; the settings "Time of day" slider (`DayNight.SetTime`: shifts the clock when the cycle runs, sets the fixed time when off; not saved) sets the hour; `--time=0..1` fixes it (0 midnight, 0.5 noon). **Natural enemies** (`EnemySpawner`, host only): every ~2.5 s one attempt near a random player, 18 to 42 m away on the surface, only where the chunk has collision and nobody is looking that way, up to 2 enemies per player by day and 7 by night; an enemy more than 75 m from everyone (or over the cap and past 42 m) with no target goes after 8 s. The old start ring is gone; `--no-enemies` disables it. The sword is the **Copper Sword** (`data/items/copper_sword.tres`, NetId 1; copper and wood handle materials are in `GameMaterials`).
- **Debug settings:** the settings panel (main menu and pause menu share it) ends with a Debug section; `GameSettings.MoveSpeedMultiplier` (0.25x to 10x, not saved, 1x at every launch) scales walking, sprinting and flying speed. Add more debug toggles there.
- **Look-at panel:** `UI/LookAtPanel` (top centre) shows a small card with the icon and name of the block under the crosshair, from a voxel ray (14 m) each frame; the text only changes with the target. Block icons come from `ItemIconRenderer.IconForBlock`, which renders a cube of every id up to `BlockIds.MaxId` once (raise `MaxId` with each new block).
- **Enemy HP bars:** `Combat/HealthBar3D` (one billboard quad, shared shader, fill ratio as an instance shader parameter), shown only while damaged. Enemy `Health:Hp` is replicated by the enemy synchronizer so clients see it.
- **Trees** are `World/Features/TreeFeature` (engine-free): a pure function of (seed, cell) (density comes from the biome), so each chunk places the part of any nearby tree that falls inside it; add new world features beside it. Keep the 18-voxel clearing around the origin free of trees (spawn).
- Never create a Godot object per frame (chunk meshes are replaced only on remesh and the old ones are `Dispose`d; share materials; cache `StringName` statics).

## Run, verify
```
dotnet build Curitibia.csproj
Godot_..._console.exe --headless --path . --import            # load errors, .uid files
Godot_..._console.exe --path . res://scenes/main.tscn -- --seed=42 --cam=-20,34,-20,-135,-25 --screenshot=out.png   # look at it
```
Dev flags (after `--`): `--seed=N`, `--cam=x,y,z,yawDeg,pitchDeg`, `--screenshot=FILE`; networking: `--net-host`, `--net-join=CODE`, `--net-name=`, `--net-url=` (e.g. `http://127.0.0.1:8099` for the dev server), `--net-no-friends`, `--net-edit=x,y,z,id`, `--net-report-at=SEC`, `--net-quit-at=SEC` (see `NetDevHooks`), and `--no-enemies`, `--menu-page=main|host|join|settings` (with `--screenshot=FILE` on the menu scene), `--look=yawDeg,pitchDeg` (start the player aimed somewhere), `--show-self` (draw your own body; with `--cam` it spawns a visible player in front of the spectator camera, for screenshots). Two-process check: host prints `CODE xxxx`; start the client with `--net-join=xxxx` and a different `P2P_SIGNALING_HOME`; compare the `NET REPORT` lines. Local server: `go run ./cmd/devserver -bucket curitibia` inside the submodule. A compile proves nothing for networking.
First time on a machine: `git submodule update --init`, `scripts/fetch-webrtc.ps1`, `dotnet build`.

## Build and release
- `build.ps1` / `build.sh` export Windows and Linux with the presets in `export_presets.cfg` into the git-ignored `build/` (`-Package` also makes `Curitibia-windows.zip` and `Curitibia-linux.tar.gz`); `-InstallTemplates` fetches the matching export templates. Godot is found through `-Godot`, `$GODOT`, a git-ignored one-line `.godot-path` file, or PATH. Full instructions in [BUILDING.md](BUILDING.md).
- **Godot needs `Curitibia.sln`** (it lists the game and the test project) to export C# projects: without it the export "succeeds" with warnings and the build has no game assemblies (no `data_Curitibia_*` folder).
- The build refuses to run without the submodule and `addons/webrtc_native` (run `scripts/fetch-webrtc.ps1` once). Each build folder gets `version.txt` (the tag in CI, else `git describe`) and the updater from `scripts/update/` (`Update.bat` + `update.ps1`, `update.sh`); the game reports that version to the signaling server (`NetSession.GameVersion`, `dev` from source).
- Releases: push a tag `v*` on a commit on `main` (plain `vX.Y.Z`, never `-rc`); `.github/workflows/release.yml` runs the unit tests, builds with `build.sh --package` and publishes the two assets. The README's one-line downloads use those exact asset names.
- **Testing an export:** release templates refuse a scene path on the command line, so use the menu's dev flags: `Curitibia.exe -- --solo --seed=42` (or `--net-host`, `--net-join=CODE`) plus `--screenshot=FILE`, `--quit-after N`.

## Status
Done and verified: voxel terrain (streaming, threaded gen + mesh, per-frame upload budget), first-person player (walk, jump, 1-block step-up, block break/place with highlight, hotbar 1-2/wheel), menu (solo, host, join by code, friends list), hosting/joining on the real server, spawn replication, host-authoritative block edits, late-join sync, **enemies** (host-run AI: vision cone + line of sight, awareness radius, 3 s memory, chase/search/wander, voxel A* pathfinding that follows the changing world, shooting), **projectiles and health** (host-decided damage with knockback, death and respawn after 3 s, replicated Hp), multiplayer UI (menu pages with a friends' room list that refreshes by itself, add friends by ID, server setting; in the world a pause menu with the big room code and players, a Tab roster with HP, join/leave toasts, a "Joining" card; failures return to the menu with a plain-language reason) and HUD (hp, room code, death banner), **field of view** (Settings page slider 60-120, default 90 vertical, in `GameSettings`, applied live), **the Unity characters** (blue-bodied player and Among-Us-style crewmate enemy built from capsules, with the Unity animation: body faces the travel direction, leans and rolls into turns, held pose in the air, wall-run pose), **materials and shaders** (Unity matte/metal/reflective materials in `GameMaterials`, the trail shader on projectiles via `RibbonTrail`, the Fresnel shader as the dead-player ghost), **enemy contact knockback**, and **controller support** (sticks with a fine-aim curve, A jump, triggers break/place, bumpers change block, Start pause, d-pad/A in menus, rumble on knockback).
Not ported on purpose: the Industrial Tiles PBR texture set and `GroundMat` (the old test ground, nothing used it; recover with `git show 0829fca:Assets/Textures/IndustrialTiles/...`), touch/XR bindings, the Unity debug-line drawing. Not done yet: enemies do not respawn once killed; item/inventory system beyond the sword and block hotbar (`Item`/`ItemAction` idea from the Unity skeleton, ask the friend what was intended); more block types (dirt, sand, snow exist but are not placeable yet); cactus/desert and snow features, water, rivers, biome name on the HUD; pause menu beyond the Leave button; a roster/ping display; export presets and CI.

## Known architectural debt
- Block break/place waits one network round trip on a client (no prediction).
- Host-side edit validation uses the sender's replicated position; no per-block permission rules.
- Block types are a static table (`BlockIds`), not `.tres` data yet.
- Border chunks re-mesh through the version counter; worker meshing may read a neighbour array while the main thread edits it (a later remesh corrects any glitch).
- Players have no health, damage or respawn rules beyond falling out of the world.
- Enemies and projectiles are not lag-compensated; a client sees them about one snapshot behind.
- Wander/chase pathing runs on the main thread (a few hundred nodes per query); move to a worker if many enemies are needed.
